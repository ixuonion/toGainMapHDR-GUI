# GainMapHDR · macOS 27 新 UI demo 与迭代方案

日期：2026-09-16。设计与实现基于当前仓库 SwiftUI GUI、现有 ConversionStore 和内置 toGainMapHDR；不是重新实现 CLI。

## 交付与启动

这是可执行的原生 SwiftUI demo，接入真实转换后端。默认仍进入原界面；通过菜单「界面 → macOS 27 新界面 Demo」（⌘⌥2）切换，输入与设置沿用同一个 Store。转换期间禁用界面切换。

```sh
bash script/build_and_run.sh --package
open -n dist/GainMapHDR.app --args --ui-demo
```

需要 Xcode 27 构建；demo 在 macOS 27 可用，原界面部署目标仍为 macOS 26。也可双击 `script/run_ui_demo.command` 构建并启动；现有构建脚本会关闭旧实例。不要同时运行多个实例向同一输出目录转换。

## 设计方向：素材、工作区、检查器

左侧显示本批次源文件、数量和移除入口；中央显示选中源图及输出摘要，转换后出现逐文件队列；右侧为可收起的参数检查器。命令和日志放入可收起的底部诊断面板。窗口底部持续显示状态，主工具栏固定提供转换/取消入口。

主要使用原生 SwiftUI List、Form、Toolbar 和语义颜色；工具栏外观交给系统，三栏采用显式宽度约束。内容区域使用清晰底色，不在图片和长文本上叠玻璃。正文沿用系统字体，副文本只用于提示与路径。错误同时提供图标、文字和详情，不单靠颜色。

默认窗口 1280 × 820；demo 最小 980 × 620。检查器可收起，侧栏可通过工具栏按钮折叠；中央和设置区域各自滚动，主操作留在工具栏。高级参数默认折叠，降低首次使用负担。

| 半尺寸、单色 Gain Map、并发数 | 高级折叠区 | 全部保留 |
| 转换、取消、进度、逐文件状态 | 工具栏、底栏、中央队列 | 真实后端，无模拟进度 |
| 输出目录定位 | 底部文件夹按钮 | 复用访达入口 |
| 命令、日志 | 工具栏「命令与日志」 | 增加命令复制；保留文本选择 |

| 源图查看 | 中央缩略图、访达定位 | 新增；非 HDR 输出预览 |

设置为批次全局设置，选中某张图片不会变成单图参数。新检查器在运行时锁定，避免参数看似变化但当前任务仍用旧快照。

现有「源文件夹」语义是**整批输出到第一张图所在目录**；demo 明示这一行为，没有擅自改变 CLI 参数。命令面板显示第一张图片的代表命令，不是所有任务的串行脚本。进度是已结束任务比例，不是单图编码进度。

## macOS 27 对齐与适用边界

| 平台依据 | 本项目决策 | 阶段 |
|---|---|---|
| macOS 27 系统外观改进 | 使用原生工具栏、分组表单和系统材质；避免仿制系统玻璃 | 本 demo |
| 工具栏相对可见性优先级 | 使用 `ToolbarItemVisibilityPriority(higherThan: .high)` 优先保留转换/取消 | 本 demo，限制在 macOS 27 |
| SwiftUI 27 任意容器重排序 | 后续为批次增加拖动排序，沿用稳定 ImageInput.id | P2 |
| item binding 警告/确认 | 后续用具体任务对象呈现失败详情与覆盖冲突 | P1/P2 |
| State 宏和 ContentBuilder 变化 | 使用当前 Xcode 27 编译检查；避免不必要自定义 State 初始化 | 本 demo |

`.topBarPinnedTrailing`、`ToolbarOverflowMenu` 不是 macOS 的可用 API，本 demo 不照搬 iPhone 工具栏。侧滑动作也不替代 Mac 的右键、键盘和显式移除按钮。网络 AsyncImage 缓存不是本地图片浏览的解决方案；demo 使用 ImageIO 后台缩略图，最长边 1600 像素，选图切换时丢弃过期结果。

以上为设计取舍，不把所有 SDK 新能力当成强制规范。当前产品是批量转换器，不必为外观升级改造成 DocumentGroup 文档应用；App Intents、持久化工作区和系统自动化可以独立评估。

## 分阶段迭代

### P0 · 本次：结构验证和原生 demo

交付原界面开关、三栏工作区、源图预览、完整参数、真实转换及诊断入口。验收以相同设置产生相同 ConversionCommand 为基础；导入、取消、错误和输出定位均应可操作。界面开关允许低成本对比旧版与新版。

### P1 · 生产可靠性与可访问性（建议 3–5 个工作日）

1. 修正 Store 层的运行状态边界：菜单导入与后台扫描完成时也要尊重运行锁；取消后等待全部任务收束，避免快速重启时旧任务回写新队列。
2. 为输出重名定义跳过/重命名/覆盖策略；明确多源目录导出策略。在策略完成前不要将 demo 当作无风险覆盖工作流。
3. 检测后端与目标目录可用性，在启动前给出明确错误；补充不可读文件、空目录、重复导入、退出时任务处理。
4. 完成 VoiceOver 顺序、全键盘操作、增加对比度、减少透明度和减少动态效果验证；覆盖中英长路径、窄窗口和多显示器。
5. 解决窗口级状态：当前 Store 与界面开关是 App 级状态，新窗口共享队列；正式版应决定单工作窗口还是每窗口独立批次，并采用 focused scene commands。

验收：快速取消/重启不串任务；既有输出不会意外覆盖；菜单、工具栏与快捷键使用同一状态约束；所有控件有可读名称和可见焦点。

### P2 · 批次效率（建议 3–5 个工作日）

增加文件拖入与文件夹扫描进度、查找/筛选、批量选择、稳定排序、失败项重试和参数预设。采用 27 的 reorderable API 时，仅在未运行队列上编辑顺序，并明确并发下“提交顺序”不等于“完成顺序”。为缩略图引入限额缓存与取消解码策略，测量 100/1000 张图片场景。

验收：千图列表滚动保持响应；重复导入不重复排队；重试仅触发失败项；预设改动有可见摘要，测试保证实际 CLI 参数一致。

### P3 · HDR 专业查看与发布（建议 5–8 个工作日）

建立源图/输出图对照、缩放、色域与位深元数据、Gain Map 检查和真实 EDR 显示管线。原图、SDR tone map 与最终输出必须区分；不能用调亮缩略图模拟 HDR。补齐非 HDR 显示器降级、系统亮度与 headroom 变化、不同显示器间拖动验证。

完成 Instruments 性能/内存检查、签名公证、发布包与 macOS 26 回归。通过特性开关分批切换默认界面，保留一个版本的旧入口。

验收：标准 HDR 样本和输出元数据验证通过，EDR/SDR 显示语义准确，旧 GUI/CLI 转换回归通过后才切换默认 UI。

工期为单开发者估算，不包含 CLI 编码缺陷修复与外部评审等待。

## 实测记录

- Xcode 27 / Swift 6.4：最终构建、打包和临时签名通过；原有 3 项命令生成与数值范围测试全部通过，`git diff --check` 通过。
- 原生 UI：检查了空态、菜单切换、参数面板、高级展开、诊断面板和窗口缩放。早期版本完成了文件导入与源图路径呈现。
- 最终版采用显式三栏布局，规避实机复现的嵌套 NavigationSplitView/Inspector 布局循环。暂不支持拖拽调整栏宽，纳入 P1 重新评估。
- 最终版自动化文件选择器的确认按钮处于禁用状态，截图工具持续返回系统窗口缩略态。因此未完成最终版 GUI 全流程和高清截图验收，需人工从启动入口复核导入。
- 独立运行打包内的 CLI：使用系统壁纸的临时副本，成功生成 6016 × 6016 HEIC，退出码 0。输出为 `/tmp/gainmaphdr-ui-demo-output/sample-HDR.heic`。CLI 将样本识别为 SDR，不构成 HDR 画质测试；受限沙盒执行时曾崩溃，正常服务访问下通过。
- 未验证：真实 HDR/EDR 显示、浅色主题、中文运行时布局、VoiceOver、macOS 26 实机、长时批次与取消重启。

## 已知边界

- demo 不修改转换引擎，也没有增加真正的输出 HDR 对比、历史记录或参数预设。
- ImageIO 无法解码的文件会显示明确空态，仍可交给 CLI；本地预览支持范围不等于 CLI 支持范围。
- 真实色彩效果、macOS 26 运行时兼容性和辅助功能矩阵需单独验收，不能仅由编译成功推断。
- 保留原 Store 已存在的取消竞态、输出命名碰撞和 App 级共享状态，纳入 P1。

## 2026-09-17 · 表单与运行反馈细化

- 高级设置改为可折叠 Section，展开子项直接参与同一原生 Form 布局，不再嵌套 DisclosureGroup。滑块、开关、并发项各自为独立行，系统统一提供内边距和分隔线；并发数值靠右。
- 移除 demo 滑块的 `step` 参数，采用无刻度连续轨道；质量仍通过 Binding 四舍五入为整数。原界面和动效预览窗口的滑块也使用连续轨道。
- 三栏标题区统一 72pt、底栏统一 44pt；中央标题移出滚动区，纵向栏线保持贯通。高级参数独立滚动，不挤压底栏。布局基准由 `StudioLayout` 集中定义。
- 运行进度采用蓝／青／靛色流光与细亮边，4 秒平滑往返，最高 30fps；填充宽度始终来自真实进度。0% 不绘制虚假填充，取消或停止后停动画。减少动态效果时静态呈现，增加对比度时使用单色；应用非活跃时暂停时间线。
- 通过系统 ProgressView 保留辅助功能百分比语义。新增「界面 → 进度动效预览」，可独立调整 0–100% 与运行状态，不触发文件转换。
- 实测：浅色原生窗口中的高级展开/滚动、标题与底栏对齐、无刻度滑块、进度预览 0% / 42% / 100% 和停止状态；构建、打包、3 项现有测试及 diff 检查通过。减少动态效果由系统环境值驱动，未修改用户系统设置做实机验证。窗口拖拽缩放尝试未改变尺寸，最小尺寸与暗色组合仍应在后续验收覆盖。
- 截图：`refined-inspector.png`。动效依据 [Apple Motion HIG](https://developer.apple.com/design/human-interface-guidelines/motion)：反馈应服务状态理解，避免不必要的位移，并尊重辅助功能设置；这不是 Apple 官方认证。
